# AGENTS.md — TrainPilot

## Commands
- Install: `uv sync` (requires Python >=3.10, repo pins 3.13 in `.python-version`)
- Test all: `uv run pytest` (`pythonpath=["src","."]`, `testpaths=["tests"]` per `pyproject.toml`)
- Single test: `uv run pytest tests/test_mailbox.py -v` (or `-k <name>` for one case)
- E2E sim (needs server running): `./start.sh` then `uv run python examples/mock_training.py [gateway_url] [task_id]`
- Server: `./start.sh` (foreground) / `./start.sh --daemon` / `./start.sh --status` / `./start.sh --stop`; overrides: `-p <PORT>`, `-H <HOST>`
- Docker: `docker build -t trainpilot:latest .` + `docker run -d -p 28780:28780 -v $(pwd)/trainpilot.db:/app/trainpilot.db -v $(pwd)/.env:/app/.env:ro --restart always trainpilot:latest`
- No lint/typecheck/CI configured — pytest is the only verification.

## Architecture
- `src/trainpilot/server/` — FastAPI control plane; entrypoint `trainpilot.server.main:app` (`trainpilot-server`). Key files: `main.py` (mounts Streamable HTTP MCP at `/mcp`), `mcp_server.py` (5 tools: `report` [unified milestone/alert/completed/failed; response always carries `next_task_plans`], `poll_instruction`, `ack_instruction`, `get_task_status`, `ack_plan`; `task_id` optional, falls back to `settings.task_id`; no resources), `mailbox.py` (in-memory scheduler + long-poll wakeup), `plans.py` (`PlanRegistry` for Feishu-queued next-task plans), `storage.py` (SQLite WAL), `cleanup.py` (task & retention cleanup service), `config.py` (pydantic-settings, prefix `TRAINPILOT_`), `routes/` (operator REST only), `feishu/` (`inbound.py` parses inbound `im.message.receive_v1` events).
- `src/trainpilot/agent/` — GPU-side MCP client: `mcp_client.py` (`TrainPilotMCPClient`) and `cli.py` (`trainpilot-cli`, subcommands `report`/`poll`/`ack`/`status`/`ack-plan`). There is no in-script HITL loop: the GPU-side AI agent (Claude Code / OpenCode) watches training and drives the protocol itself.
- `src/trainpilot/common/` — `states.py` (`TaskState`: RUNNING→WAITING→RESOLVED→RECOVERING→RUNNING/COMPLETED/FAILED; `ActionType`: `stop_training`/`self_resolve`/`custom` — the actions an agent can receive; the alert card's `wait_for_arrangement` button is a `WAIT_FOR_ARRANGEMENT` module constant instead, since it is a card-only control action that is never delivered to anyone), `schemas.py`, `gateway.py` (address resolution, shared by server+agent).
- Endpoints: `/mcp` (MCP), `/docs`, `/health`, `/ready`, `/webhook/feishu`, `/api/tasks/...`.

## Gotchas
- **Single worker only.** Mailbox long-poll locks are in-process; never pass `--workers >1` to uvicorn (`start.sh` and `Dockerfile` already enforce this; scale via `task_id`-hash proxy).
- **`TRAINPILOT_HOST` has dual meaning** (`common/gateway.py`, `server/config.py`, `start.sh:resolve_bind_host`): server side = bind address (only local values `0.0.0.0`/`127.0.0.1`/`localhost` honored, public IP silently falls back to `0.0.0.0`); GPU side = gateway host. Server bind → use `TRAINPILOT_BIND_HOST`; client URL → use `TRAINPILOT_GATEWAY_URL` (highest priority) or `TRAINPILOT_HOST`+`TRAINPILOT_PORT`. Never copy a public IP into the server's `TRAINPILOT_HOST` expecting it to bind.
- **`.env` is per-machine, two modules** (`cp .env.example .env`; `start.sh` auto-creates it): Module 1 = public server, Module 2 = GPU client. Defaults: port `28780`, alert timeout `30s`, long-poll `20s`.
- **The agent-facing contract lives in exactly one place:** `mcp_server._INSTRUCTIONS` plus the five tool docstrings. README and AGENTS.md must point at it, never restate the rules — duplicated rule text is what drifts.
- **Task rows are created only by `report`/`record_event`.** Never build task state from a request path, header, or client IP; reading an unknown `task_id` must return not-found, not fabricate a `RUNNING` row. The plan path in particular must never call `record_event`/`_get_or_create`: a plan may name a task that does not exist yet, and `tests/test_plans.py::test_registering_a_bound_plan_does_not_create_a_task_row` pins it.
- **Next-task plans: `@bot` in the group *is* the trigger — there is no keyword prefix**, by explicit product decision. Inbound parsing lives in `server/feishu/inbound.py` (pure, no I/O); `routes/webhook.py` must branch on `is_message_event(data)` *before* the card-action early return. Idempotency is `UNIQUE(source_message_id)` + `INSERT OR IGNORE`, and the receipt card is dispatched only when the row was actually created — Feishu redelivers events it cannot confirm in ~3s. `PlanRegistry` reuses `default_mailbox._storage` (one connection, one lock, and it inherits conftest's DB redirect) — never open a second `SQLiteStorage`. Pending plans are exempt from cleanup (`delete_expired_plans` only reaps acked ones), so `report` keeps re-surfacing them until `ack_plan` or a clear command. Plans go into `report` under `next_task_plans`/`next_task_plans_guidance`; alert's `next_action`/`guidance` keys are a separate, test-pinned contract — do not merge them. The same inbound parser also recognises `#fix(任务名) <方案>` (dispatched as the alert's decision, `action="custom"`, solution in `payload["solution"]`) and `#feat(任务名) <计划>` (identical to the bare `#任务名` tag); `#fix` is parsed first and wins, and its body is kept verbatim.
- **`#fix` is gated inside the mailbox, never in the webhook.** `TaskMailboxManager.submit_fix_decision` does the state check *and* the `source_message_id` de-dupe in one critical section under the existing lock, returning `(instruction, created)`; a get-then-submit gate in `routes/webhook.py` would race a concurrent button click. It uses `_get_existing`, so an unknown id raises `TaskNotFoundError` and **no task row is ever created** — the same rule the plan path follows. `tests/test_server_api.py` pins the receipt-card-only-on-`created` behaviour.
- **「等待安排」 is a persisted second auto-resolve stage.** The card click writes `arrangement_requested_at/by` on the task (plain column semantics — NULL means cleared, deliberately *not* the `feishu_message_id` COALESCE), leaves state/`pending_instruction` untouched, and arms `schedule_auto_resolve(stage="arrangement")`. `try_auto_resolve(..., stage=...)` makes the two windows mutually exclusive: the alert stage no-ops while the window is open, the arrangement stage no-ops without it. Any queued instruction closes the window via `_clear_arrangement`, as does a non-duplicate fresh alert — without that, the next alert's 30s timer could never fire again.
- **Do not commit secrets/artifacts.** `.env` (has real tokens), `trainpilot.db*`, `*.log`, `.trainpilot.pid` are gitignored — never `git add` them.
- **Feishu without credentials is safe:** unconfigured → Mock mode logs cards to console. Use `TRAINPILOT_ENABLE_MOCK_FEISHU=true` for local tests.
- **Test isolation is centralized in `tests/conftest.py`** and covers every suite: it redirects `settings.sqlite_path` to a temp DB *before* `trainpilot.server.mailbox` is imported (the default is the relative `trainpilot.db`, and mailbox teardown issues `DELETE FROM tasks` — an unredirected run wipes the local dev database), then resets `default_mailbox` and nulls `api_token`/`feishu_verification_token` around each test. Don't re-declare those fixtures per module. `test_e2e_simulation.py` boots live uvicorn on port `18925`, runs the example in-process, and samples task state from a watcher thread to prove the HITL loop ran.
- **`TaskMailboxManager` exposes only async long polling** (`get_instruction_async`, backed by `_async_instruction_waiters`); the blocking `threading.Event` variant was removed as dead code. Callers inside sync tests must `await` it.
- **`examples/mock_training.py` is imported by a test** (`tests/test_e2e_simulation.py` → `run_mock_training`, resolved via `pythonpath=["src","."]`). Keep it importable and keep the `examples/` directory non-empty — the `Dockerfile` COPYs it.
- **Auth split:** MCP/REST use `Authorization: Bearer <TRAINPILOT_API_TOKEN>` (or `X-API-Token`); `/webhook/feishu` uses `TRAINPILOT_FEISHU_VERIFICATION_TOKEN` instead and is unaffected by API token.
